# Velvet internationalization convention

Velvet supports `pt-BR` (default) and `en`. Existing URLs remain the canonical
Portuguese experience; English uses the same stable route and slug structure
under `/en` (for example `/perfil/ana` and `/en/perfil/ana`). The proxy rewrites
the English prefix internally, so authentication, Server Actions and provider
callbacks continue to target the established application routes.

User-facing system copy belongs in the typed modules under `lib/i18n/messages`.
New features must add both Portuguese and English messages, use meaningful keys,
and consume them through `getTranslations()` in Server Components or `useI18n()`
in Client Components. Do not translate persisted enum values, user-authored
profile content, slugs, provider payloads, or log messages.

Use the helpers in `lib/i18n/format.ts` for dates, numbers, and currencies. BRL
remains BRL in English; selecting a language never converts commercial values.
Add or update focused translation, routing, formatting, and metadata tests for
every new user-facing surface. Missing localized strings fall back to `pt-BR`;
development emits a warning, while production never exposes raw translation keys.
